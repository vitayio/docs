The **Notifications** tab controls the automatic emails Vitay sends about your candidates. From top to bottom it has: **Team notifications** (who is emailed about each event), **Additional report recipients**, **Email options**, **Candidate notifications**, **Auto reminders** and **Usage Notifications**.

<Note>
  You need the root recruiter role. Every switch and checkbox on the tab saves as soon as you change it. Changes apply to future emails only.
</Note>

## Choose who is notified about each event

**Team notifications** is a table. Each row is an event and each column is a group of people. Tick any combination of columns on a row.

<Steps>
  <Step title="Open the Notifications tab">
    In the Configuration area, click **Settings**, then the **Notifications** tab. **Team notifications** is the first card.

    ![SCREENSHOT(notification-settings-team-table): The Team notifications table with event rows and the Assigned recruiter, Reference requester, Root users and Additional emails columns](/images/placeholder.png)
  </Step>
  <Step title="Find the event">
    Each row names an event and says when it fires. See [Events you can be notified about](#events-you-can-be-notified-about).
  </Step>
  <Step title="Tick the recipients">
    Tick a box to add that group to the event, untick it to remove them. If a change can't be saved, the box switches back and an error appears.

    | Column | Who receives the email |
    |---|---|
    | **Assigned recruiter** | The recruiter the candidate is assigned to. |
    | **Reference requester** | The recruiter who sent the request. |
    | **Root users** | Every active team member with the Root role. |
    | **Additional emails** | Extra addresses, such as a shared inbox. No Vitay account needed. |
  </Step>
  <Step title="Add extra addresses if you need them">
    Ticking **Additional emails** opens an **Additional emails for this event** field under the row. Type an address and press **Enter**. Each event has its own list of up to 20 addresses. Click an address's **×** to remove it.
  </Step>
</Steps>

How recipients work:

- Deactivated team members are skipped.
- A person who matches several columns gets one copy.
- A row with nothing ticked sends no email. There is no separate "always notify" list.
- Team notifications name the candidate and link to their record, so only add addresses that should see that.

## Events you can be notified about

Some rows only appear when your account uses the matching feature.

| Event | When it's sent | Default for new accounts |
|---|---|---|
| **Reference completed** | A reference submitted their answers. | Assigned recruiter |
| **All references completed** | Every reference for a candidate has been submitted. | Assigned recruiter |
| **Candidate submitted their references** | A candidate provided the reference contacts you asked for. | Assigned recruiter |
| **Reference awaiting your review** | A candidate added a reference that needs approval. Shown when **Reference review configuration** is on. | Reference requester |
| **Reference or request unresponsive** | A reference or request ran out of reminders without a reply. | Assigned recruiter |
| **Email could not be delivered** | An email to a candidate or reference bounced or was rejected. | Assigned recruiter |
| **Text message could not be delivered** | A text to a candidate or reference failed. Shown when text messages are on for your account. | Assigned recruiter |
| **IP address conflict detected** | A candidate and one of their references submitted from the same IP address. | Assigned recruiter |
| **Candidate submitted their own contact details as a reference** | A candidate tried to add their own email or phone number as a reference. | Assigned recruiter |
| **Feedback completed** | A feedback request was completed. Shown when a feedback plugin is on. | Assigned recruiter and reference requester |
| **Pre-screening completed** | A pre-screening request was completed. Shown when the pre-screening plugin is on. | Assigned recruiter |
| **Lead received** | A reference asked to be contacted. Shown on the original lead generation setup only. | Assigned recruiter |

### Reference awaiting your review

When **Reference review configuration** is on (see [Reference request settings](/account-configuration/reference-request-settings)), references a candidate adds wait for approval. This row decides who is told. Untick every column to stop the email. The email shows as "*Candidate name* via *Your firm*", and replying reaches the candidate.

### When an unresponsive alert fires

A reference or reference request counts as unresponsive when it still isn't filled in, it has no more reminders scheduled, and the last reminder went out more than 24 hours ago. The alert is sent once per record. If the same reference goes quiet again later, there is no second email.

A candidate in **Process initiated** also moves to **Unresponsive** when one of their reference requests goes quiet, and moves back once it responds. See [Candidate statuses and comments](/candidates-reference-requests/candidate-statuses-and-comments).

### IP address conflicts

Vitay only checks for IP conflicts when someone would hear about them: at least one column is ticked on **IP address conflict detected**, or the **IP conflict banner** under [Email options](#email-options) is on. Otherwise no conflicts are recorded. See [IP conflicts and reference edits](/candidates-reference-requests/ip-conflicts-and-reference-edits).

### Self-reference attempts

When a candidate lists themselves as a reference, the form rejects it and the attempt is recorded on the candidate page whatever this row says. The row only decides who is emailed. Repeated attempts before someone clears the alert send one email. See [Fraud signals](/candidates-reference-requests/ip-conflicts-and-reference-edits#self-reference-attempts).

### Lead notifications

On the original lead generation setup, the **Lead received** row sends lead emails. If your account collects hiring leads this way, the **Additional emails** column shows a **Manage list** button. Click it to choose addresses and the lead types each one receives. On the current lead generation setup, you choose recipients per lead type instead. See [Lead generation](/reports-lead-generation/lead-generation).

## Additional report recipients

When this card is on, your users can add extra email addresses to a candidate. Those addresses get the same confidential reference report emails as the assigned recruiter, for example a hiring manager without a Vitay login. A candidate can have up to five.

Turn on **Restrict to your organization's domains** to accept only addresses whose domain matches one used by an active recruiter in your firm.

<Warning>
  Report recipients receive confidential reference content by email. Use the domain restriction if reports should never leave your organisation. See [Share reports](/candidates-reference-requests/share-reports).
</Warning>

## Email options

| Option | What it does | Default |
|---|---|---|
| **Attach the PDF report to completion emails** | Adds the report as a PDF to reference-completed, all-references-completed and feedback-completed emails to your team. | Off |
| **IP conflict banner** | Shows a banner on reports when the candidate and reference share an IP address, or the candidate tried to add themselves as a reference. Appears only while the PDF option above is on. | Off |
| **Requested user email** | Sends candidate and reference emails in the name of the recruiter who sent the request, not the assigned recruiter. | Off |

## Candidate notifications

| Switch | What it does | Default |
|---|---|---|
| **Candidate: Reference has been added** | Emails the candidate when a user adds a reference for them. | Off |
| **Candidate reference pending notification** | Emails the candidate when one of their references still hasn't responded. Its wording is the **Candidate: Reference response still pending** template on the **Emails** tab, shown only while this is on. | On |
| **Candidate: Reference is completed** | Emails the candidate when a reference is completed. | On |
| **Candidate: Notify Reference Contact Errors** | Emails the candidate when an email or text to one of their references can't be delivered, so they can correct it. Only sent when someone on your team is also notified about that failure. | Off |

See [Email and text delivery](/candidates-reference-requests/email-and-text-delivery).

## Auto reminders

The **Auto reminders** card turns the automatic reminder sequence on or off and sets the **Reminders Rate** and **Skip Reminders during the weekend**. See [Reminders and how they work](/candidates-reference-requests/reminders-and-cadence).

**Feedback reminders** (on by default) controls reminders for feedback requests. Turn it off to send feedback recipients the original request only, while reference reminders carry on. It appears when **Auto reminders** is on and a feedback plugin is on. See [Candidate feedback](/feedback/candidate-feedback).

## Usage notifications

**Usage Notifications** email your team as usage approaches your contract limits. New accounts start with it on, the 80%, 90% and 100% thresholds ticked, and **Notify Administrators** on.

<Steps>
  <Step title="Turn on Usage Notifications">
    On the **Notifications** tab, switch on **Usage Notifications**.

    ![SCREENSHOT(notification-settings-usage): The Usage Notifications card with the threshold checkboxes, Notify Administrators switch and Additional Email Recipients field](/images/placeholder.png)
  </Step>
  <Step title="Pick your thresholds">
    Under **Notification Thresholds**, tick the percentages of your contract limit that should send an alert.
  </Step>
  <Step title="Choose who hears about it">
    **Notify Administrators** emails every root user. **Additional Email Recipients** takes a comma-separated list of extra addresses, such as a finance inbox.
  </Step>
</Steps>

Each threshold sends one email per contract period and resets when a new period starts. Usage across your sub-accounts counts toward the parent account. See [Billing and usage](/account-configuration/billing-and-usage).

## Troubleshooting

<AccordionGroup>
  <Accordion title="I'm not receiving notifications I expect">
    Find the event's row under **Team notifications** and check that a column that includes you is ticked. If only **Assigned recruiter** is ticked, you only hear about candidates assigned to you. To get every notification, ask a root recruiter to tick **Root users** (if you are root) or add your address under **Additional emails** on each row. Also check spam, and that your firm's sender domain is authenticated (see [Email sender settings](/account-configuration/email-sender-settings#which-sender-your-team-sees)).
  </Accordion>
  <Accordion title="Too many people are getting notified">
    Untick the columns you don't need on each row. If someone still gets everything, check whether they are root (**Root users** includes every active root user) or listed under **Additional emails**.
  </Accordion>
  <Accordion title="I don't see a row for an event">
    Rows follow the features your account uses: **Feedback completed** and **Pre-screening completed** need their plugins, **Text message could not be delivered** needs text messages, and **Reference awaiting your review** needs **Reference review configuration**. Contact **hello@vitay.io** if a feature should be available to you.
  </Accordion>
  <Accordion title="Team notifications could not be loaded">
    Refresh the page. If the table still doesn't load, contact **hello@vitay.io**.
  </Accordion>
</AccordionGroup>
