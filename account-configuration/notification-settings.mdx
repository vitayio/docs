---
title: "Notification settings"
description: "Choose who on your team is emailed about completed references, feedback, delivery failures and other events, and which emails candidates receive."
---

The **Notifications** tab controls every automatic email Vitay sends about your candidates: who on your team hears about each event, how those emails are sent, and which updates candidates receive. It is grouped by audience, top to bottom:

1. **Team notifications**: who is emailed when each event happens.
2. **Always notified team members**: people who receive every team notification.
3. **Additional report recipients**: extra addresses on individual candidates.
4. **Email options**: how team notifications are sent.
5. **Candidate notifications**: emails candidates receive about their own references.
6. **Auto reminders** and **Usage Notifications**.

<Note>
  You need a **root recruiter** role to open **Configuration → Settings → Notifications**. Every switch and checkbox on the tab saves as soon as you change it; there is no Save button. Changes apply to future emails only.
</Note>

## Choose who is notified about each event

**Team notifications** is a table. Each row is an event, and each column is a group of people who can be emailed when it happens. Tick any combination of columns on a row.

<Steps>
  <Step title="Open the Notifications tab">
    Go to **Configuration → Settings → Notifications**. **Team notifications** is the first card.

    ![SCREENSHOT: The Team notifications table on Settings → Notifications, showing event rows and the Assigned recruiter, Reference requester, Root users and Additional emails columns — placeholder](/images/placeholder.png)
  </Step>
  <Step title="Find the event">
    Each row names the event and describes when it fires, for example **Reference completed** or **Email could not be delivered**. See [Events you can be notified about](#events-you-can-be-notified-about) for the full list.
  </Step>
  <Step title="Tick the recipients">
    Tick a box to add that group of people to the event, and untick it to remove them. Each box saves on its own and a confirmation message appears. If a change can't be saved, the box switches back and an error message appears.

    | Column | Who receives the email |
    |---|---|
    | **Assigned recruiter** | The recruiter the candidate is assigned to. |
    | **Reference requester** | The recruiter who sent the request. Often the same person as the assigned recruiter. |
    | **Root users** | Every active team member with the Root role. |
    | **Additional emails** | Extra addresses such as a shared inbox. They receive the email without needing a Vitay account. |

    Hover the question-mark icon next to a column heading to see the same explanation in the app.
  </Step>
  <Step title="Add extra addresses if you need them">
    Ticking **Additional emails** opens an **Additional emails for this event** field under that row. Type an address and press **Enter** to add it. You can add up to 20 addresses per event, and remove one by clicking its **×**. Each event has its own list.
  </Step>
</Steps>

Some things to know about recipients:

- **Only active people are emailed.** Team members whose account has been deactivated are skipped automatically.
- **Nobody gets the same email twice.** If one person matches several columns (for example, they are both the assigned recruiter and a root user), they receive one copy.
- **An event with nobody ticked sends no email**, unless someone is on the [always notified](#always-notify-a-team-member) list.
- **Additional emails reach people outside Vitay.** Team notifications name the candidate and link to their record, so only add addresses that should see that information.

<Note>
  If your account was set up before the Notifications tab was reorganized, Vitay carried your existing choices over, so each event goes to the same people as before. One difference: **Root users** now means every active root user in your account, not just the account's main root address.
</Note>

## Events you can be notified about

Rows only appear for features your account uses. For example, **Feedback completed** appears only when a feedback plugin is active.

| Event | When it's sent | Default for new accounts |
|---|---|---|
| **Reference completed** | A reference has submitted their answers for a candidate. | Assigned recruiter |
| **All references completed** | Every reference for a candidate has been submitted. | Assigned recruiter |
| **Candidate submitted their references** | A candidate has provided the reference contacts you asked for. | Assigned recruiter |
| **Reference awaiting your review** | A candidate added a reference that needs approval before the question set is sent. Only shown when **Reference review configuration** is on. | Reference requester |
| **Reference or request unresponsive** | A reference or reference request has run out of reminders without a reply. | Assigned recruiter |
| **Email could not be delivered** | An email to a candidate or reference bounced or was rejected. | Assigned recruiter |
| **Text message could not be delivered** | A text message to a candidate or reference failed. Only shown when text messages are enabled for your account. | Nobody (off) |
| **IP address conflict detected** | A candidate and one of their references submitted from the same IP address. | Assigned recruiter |
| **Feedback completed** | A feedback request has been completed. Only shown when a feedback plugin is active. | Assigned recruiter and reference requester |
| **Pre-screening completed** | A pre-screening request has been completed. Only shown when the pre-screening plugin is active. | Assigned recruiter |
| **Lead received** | A reference asked to be contacted. Only shown for accounts on the original lead generation setup. | Assigned recruiter |

### Reference awaiting your review

When **Reference review configuration** is on (see [Reference request settings](/account-configuration/reference-request-settings)), references a candidate adds are held until someone approves them. This row decides who is told that a reference is waiting. You can send it to the requester, the assigned recruiter, root users or extra addresses, or untick every column to stop the email. Each recipient gets their own copy.

### When an unresponsive alert fires

A reference or reference request is treated as unresponsive when all of the following are true:

- it still hasn't been filled in;
- its automatic reminders have run out, so no further reminder is scheduled; and
- the last reminder went out more than 24 hours ago.

Vitay then emails the people ticked on **Reference or request unresponsive**. The alert is sent **once per record**. If the same reference goes quiet again later, you won't get a second email, so check the record itself for its current state.

<Note>
  Separately, a candidate sitting in **Process initiated** is moved to the **Unresponsive** status when one of their reference requests goes quiet, and moves back automatically once it's responsive again. See
  [Candidate statuses and comments](/candidates-reference-requests/candidate-statuses-and-comments).
</Note>

### IP address conflicts

Vitay only checks for IP conflicts while someone would be told about them: at least one column is ticked on **IP address conflict detected**, or the **IP conflict banner** under [Email options](#email-options) is on. If neither is true, no conflicts are recorded. Adding someone to the always notified list doesn't turn the check on by itself. See [IP conflicts and reference edits](/candidates-reference-requests/ip-conflicts-and-reference-edits).

### Lead notifications

On accounts that use the original lead generation setup, the **Lead received** row sends lead emails. If your account collects hiring leads this way, the **Additional emails** column shows a **Manage list** button instead of a checkbox. Click it to edit the list of addresses and which lead types each one receives. Accounts on the current lead generation setup choose lead recipients per lead type instead. See [Lead generation](/reports-lead-generation/lead-generation).

## Always notify a team member

**Always notified team members** lists every active user on your account. Anyone with **Always notify** switched on receives every team notification in the table above, whatever the columns say. This suits a team lead who wants to see everything.

<Steps>
  <Step title="Find the person">
    On **Settings → Notifications**, scroll to **Always notified team members**. Each row shows the person's name and email.

    ![SCREENSHOT: The Always notified team members card with the Name, Email and Always notify columns — placeholder](/images/placeholder.png)
  </Step>
  <Step title="Switch Always notify on or off">
    Flip the **Always notify** switch on their row. It saves straight away.
  </Step>
</Steps>

Always notified team members don't receive lead emails on the current lead generation setup (those are set per lead type), usage alerts, or the report emails sent to additional report recipients.

## Additional report recipients

**Additional report recipients** lets your users add extra email addresses to an individual candidate. Those addresses then receive the same confidential reference report emails as the assigned recruiter. This is useful for a hiring manager or client contact who should see the result without a Vitay login.

- A candidate can have at most **five** report recipients.
- Turn on **Restrict to your organization's domains** to only accept addresses whose domain matches one already used by an active recruiter in your firm. Anything else is rejected when it's added.

<Warning>
  Report recipients receive confidential reference content by email. Use the domain restriction if
  reports should never leave your organisation. See
  [Share reports](/candidates-reference-requests/share-reports).
</Warning>

## Email options

**Email options** controls how the team notifications above are sent.

| Option | What it does | Default |
|---|---|---|
| **Attach the PDF report to completion emails** | Reference-completed, all-references-completed and feedback-completed emails to your team include the report as a PDF, so it arrives in the inbox. Leave it off if reports should only be read inside Vitay. | Off |
| **IP conflict banner** | Shows a banner on reports when the candidate and reference share the same IP address. It sits under **Attach the PDF report to completion emails** and only appears while that option is on. | Off |
| **Requested user email** | Emails to candidates and references are sent in the name of the recruiter who sent the request, instead of the candidate's assigned recruiter. | Off |

## Candidate notifications

**Candidate notifications** are emails Vitay sends to candidates about their own references. Each switch saves as soon as you flip it.

| Switch | What it does | Default |
|---|---|---|
| **Candidate: Reference has been added** | Notify the candidate when a user has added a new reference. | Off |
| **Candidate reference pending notification** | Notify the candidate when their reference is pending. | On |
| **Candidate: Reference is completed** | Notify the candidate when their reference is completed. | On |
| **Candidate: Notify Reference Contact Errors** | Notify the candidate when Vitay can't deliver an email or text to one of their references, so they can supply better contact details. | Off |

**Candidate: Notify Reference Contact Errors** is only sent when someone on your team is also notified about the same failure (see [Email and text delivery](/candidates-reference-requests/email-and-text-delivery)).

## Auto reminders

The **Auto reminders** card controls the automatic reminder sequence for candidates and references: whether it runs, the **Reminders Rate**, and **Skip Reminders during the weekend**. See [Reminders and how they work](/candidates-reference-requests/reminders-and-cadence).

Inside it, **Feedback reminders** is a separate switch:

- Leave it **on** (the default) and feedback recipients get the same reminder sequence as everyone
  else.
- Turn it **off** and recipients get the original feedback request only, with no follow-ups, while
  reference reminders carry on as normal.

<Note>
  **Feedback reminders** only appears when **Auto reminders** is on and at least one feedback type is
  enabled for your firm. See [Candidate feedback](/feedback/candidate-feedback).
</Note>

## Usage notifications

**Usage Notifications** warn your team as you approach your contract limits, so a renewal
conversation isn't a surprise.

<Steps>
  <Step title="Turn on Usage Notifications">
    On **Settings → Notifications**, switch on **Usage Notifications**.
  </Step>
  <Step title="Pick your thresholds">
    Under **Notification Thresholds**, tick the percentages of your contract limit that should
    trigger an alert. You can pick more than one, for example 80% and 100%.
  </Step>
  <Step title="Choose who hears about it">
    **Notify Administrators** sends the alert to everyone with root/administrator access.
    **Additional Email Recipients** takes a comma-separated list of extra addresses, such as your
    finance inbox.
  </Step>
</Steps>

<Note>
  Each threshold notifies you **once per contract period**. It won't repeat as usage hovers around
  the same percentage, and the set resets when a new contract period begins. Usage is counted
  across your sub-accounts as well as the parent account. See
  [Billing and usage](/account-configuration/billing-and-usage).
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="I'm not receiving notifications I expect">
    On **Settings → Notifications**, find the event's row under **Team notifications** and check that a column that includes you is ticked. For example, if only **Assigned recruiter** is ticked, you only hear about candidates assigned to you. To receive every team notification, ask a root recruiter to switch on **Always notify** for you. Also check your spam folder, because notification emails from Vitay's shared sender domain can occasionally be filtered.
  </Accordion>
  <Accordion title="Too many people are getting notified">
    Untick the columns you don't need on each row. If someone still receives everything, check whether **Always notify** is on for them under **Always notified team members**, since that overrides the columns. Remember that **Root users** includes every active root user.
  </Accordion>
  <Accordion title="I don't see a row for a particular event">
    Rows follow the features your account uses. **Feedback completed** and **Pre-screening completed** need their plugins, **Text message could not be delivered** needs text messages, and **Reference awaiting your review** needs **Reference review configuration**. Contact **hello@vitay.io** if you believe a feature should be available to your account.
  </Accordion>
  <Accordion title="Team notifications could not be loaded">
    Refresh the page to try again. If the table still doesn't load, contact **hello@vitay.io**.
  </Accordion>
</AccordionGroup>
